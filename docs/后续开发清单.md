# 后续开发清单

按依赖顺序推进：

1. **正式认证与权限**：接入登录态，将 `X-Demo-User` 替换为认证中间件注入的用户身份；补齐订单、会话、附件、售后单的归属检查。
2. **数据库迁移**：使用 Alembic 管理表结构，避免正式数据环境使用 `create_all`；补齐商品、订单、售后、工单和审计字段。
3. **知识导入与检索**：解析 Markdown/PDF/HTML，切分章节，保存政策版本与有效期；在 PostgreSQL 开启 pgvector 和全文索引，实现混合召回、重排和证据充分性判断。
4. **模型接入**：添加可配置 LLM 适配层；模型负责意图和槽位抽取及表达，业务状态和资格仍由服务端核验。
5. **状态化售后流程**：补齐多轮槽位收集、会话检查点、用户确认后恢复、资格规则版本、工单创建和人工审核队列。
6. **图片证据**：文件校验、MinIO 存储、附件权限、OCR、客观视觉摘要、售后案件关联与过期策略。
7. **可观测性**：请求 ID、运行轨迹、工具调用摘要、审计事件、延迟与失败指标；日志脱敏。
8. **评测与交付**：构建 FAQ、订单、越权、过期政策、工具失败、重复提交、图片和转人工样例；生成指标报告、ER 图、API 文档和可复现导入脚本。
