# 后续开发清单

## 本轮已经完成

1. **前端会话 epoch**：登录、退出和换号会推进会话 epoch；旧会话中晚到的异步响应不会再回写到当前账号界面。
2. **订单项唯一约束**：数据库已增加 `order_items(order_id, product_id)` 唯一约束，防止同一订单与商品组合被重复写入。
3. **Docker 镜像固定**：Compose 中使用的 PostgreSQL/pgvector、Redis、Chroma 和 Prometheus 镜像已经固定到明确 digest；MinIO 使用固定官方源码标签构建，避免 `latest` 漂移导致环境不可复现。

## 下一步优先项

### P1：认证稳定性与权限安全

1. **多标签页协调**：使用 Web Locks 或 BroadcastChannel 协调刷新令牌轮换，避免两个标签页同时刷新时，其中一个标签页因使用已撤销令牌而错误退出。
2. **登录和刷新保护**：为登录、刷新接口增加按账号与来源地址组合的限流、失败计数和安全审计；明确锁定阈值、恢复时间及统一错误响应，避免泄露账号是否存在。
3. **刷新会话生命周期**：增加 refresh token family 与替换关系；检测旧刷新令牌重放时撤销整组会话，并增加过期会话定时清理。随后设计 JWT 签名密钥版本、轮换窗口和旧密钥退出流程。
4. **客服与管理员授权范围**：在开放客服或管理员业务接口前，建立工单分配、可访问顾客范围和管理操作权限；角色只负责进入接口，具体订单、会话和售后资源仍需逐条校验范围。

### P2：兼容性与防御性改进

1. **历史旧库专用迁移**：旧版 `backend/mallmate.db` 继续只作历史备份。当前首个迁移只接管具备受支持基线全部必需列的旧表；如需导入更早版本数据，应编写一次性专用数据迁移，完成字段映射、冲突处理和导入记录。
2. **超长订单号边界**：限制 Agent 从消息中提取的订单号位数，并在进入数据库查询前验证其处于数据库整数范围内，避免超长数字触发转换或驱动异常。
3. **密码哈希参数升级**：将密码验证改为 `verify_and_update` 流程；用户登录成功时，如果 Argon2 参数已经过时，则在同一受控流程中重新生成并保存新哈希。

按依赖顺序推进：

1. **认证增强**：第一版账号、Argon2 密码、短期 JWT、刷新会话、三种角色、资源归属和 Agent 身份传递已经完成；按上面的 P1、P2 顺序补齐多标签页协调、限流、审计、会话生命周期、客服工单范围、改密和管理员 MFA。
2. **数据库扩展**：Alembic 基线和认证迁移已经完成；后续通过新 revision 补齐工单、审计和更多业务字段，不再使用 `create_all` 改表。
3. **知识导入与检索**：解析 Markdown/PDF/HTML，切分章节，保存政策版本与有效期；在 PostgreSQL 开启 pgvector 和全文索引，实现混合召回、重排和证据充分性判断。
4. **模型接入**：添加可配置 LLM 适配层；模型负责意图和槽位抽取及表达，业务状态和资格仍由服务端核验。
5. **状态化售后流程**：补齐多轮槽位收集、会话检查点、用户确认后恢复、资格规则版本、工单创建和人工审核队列。
6. **图片证据**：文件校验、MinIO 存储、附件权限、OCR、客观视觉摘要、售后案件关联与过期策略。
7. **可观测性**：请求 ID、运行轨迹、工具调用摘要、审计事件、延迟与失败指标；日志脱敏。
8. **评测与交付**：构建 FAQ、订单、越权、过期政策、工具失败、重复提交、图片和转人工样例；生成指标报告、ER 图、API 文档和可复现导入脚本。
