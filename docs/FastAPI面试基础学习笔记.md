# FastAPI 面试基础学习笔记

> 适用项目：MallMate 电商客服售后 Agent
> 范围：HTTP 与路由、Pydantic、依赖注入、同步与异步、中间件与生命周期、异常处理、数据库与 ORM、认证与授权。
> 使用方式：先读“基础知识”，再尝试回答问题，最后对照项目代码复述一遍。

## 先建立一个整体认识

FastAPI 是后端的 HTTP 接口框架。它接收浏览器或其他客户端发来的 HTTP 请求，检查输入，执行 Python 函数，然后把结果转换成 HTTP 响应。

```text
客户端请求
  → 路由匹配
  → 参数解析和校验
  → 依赖准备（用户、数据库会话、业务服务）
  → 执行业务函数
  → 处理异常或校验返回值
  → 序列化为 JSON 并返回
```

在 MallMate 中，FastAPI 路由负责 HTTP 入口，Service 负责业务规则，Repository 负责数据库查询；LangGraph 只负责聊天 Agent 的工作流编排。

## 1. HTTP 与路由

### 基础知识

HTTP 是客户端和服务器之间交换请求与响应的协议。一个请求通常包含：

- **方法**：要执行的动作，例如 GET 或 POST。
- **路径**：要访问的资源，例如 `/api/v1/orders/1001`。
- **路径参数、查询参数或请求体**：传递具体输入。
- **请求头**：传递内容类型、身份信息等元数据。

服务器返回状态码、响应头和响应体。REST API 通常用资源路径表达对象，用 HTTP 方法表达动作。

| 方法 | 常见用途 | 示例 |
|---|---|---|
| GET | 读取资源，不应产生业务写入 | 查询订单 |
| POST | 创建资源，或提交一个需要执行的动作 | 创建售后申请 |
| PUT | 用完整的新内容替换资源 | 完整替换某个配置 |
| PATCH | 只修改资源的部分字段 | 修改售后单状态 |
| DELETE | 删除资源 | 删除某条知识文档 |

路径参数标识资源；查询参数通常用于筛选、排序或分页；请求体通常承载要创建或修改的数据。FastAPI 根据路径模板、函数参数类型、默认值和 Pydantic 模型等信息解析参数：出现在路径模板中的同名参数是路径参数；简单类型通常从 Query 读取；Pydantic 模型通常从 JSON Body 读取。若需要明确表达来源，可以使用 `Path`、`Query`、`Body`。

### 常见状态码

| 状态码 | 含义 | 项目中的典型场景 |
|---:|---|---|
| 200 | 请求成功 | 查询订单成功、预览售后资格 |
| 201 | 已创建资源 | REST 风格的创建接口成功时常用；当前售后接口实际由响应模型返回结果 |
| 400 | 请求本身不符合业务或协议要求 | 参数组合不合法 |
| 401 | 未通过身份认证 | 用户没有有效登录身份 |
| 403 | 已识别身份，但没有访问权限 | 用户被明确禁止操作该资源 |
| 404 | 资源不存在，或按权限规则对当前用户不可见 | MallMate 把他人订单和不存在订单统一视为未找到 |
| 409 | 请求与当前资源状态冲突 | 幂等键被用于不同的售后申请 |
| 422 | 请求字段或格式校验未通过 | 订单号不是正整数、必填字段缺失 |
| 500 | 服务端未预期错误 | 未处理的程序异常 |

实际项目的错误状态码要以接口契约为准。不要把所有错误都返回 200，也不要把内部异常详情直接返回客户端。

### 面试问题与回答

**问：什么是 REST API？**

答：REST 是一组围绕资源组织 Web API 的设计约束。接口通常用 URL 表示资源，用 HTTP 方法表示读取、创建、更新或删除等操作，并用状态码表达处理结果。它不是某个 Python 库，也不要求 URL 必须长成唯一形式。

**问：GET、POST、PUT、PATCH、DELETE 分别适合什么场景？**

答：GET 读取；POST 创建或触发动作；PUT 完整替换；PATCH 部分更新；DELETE 删除。GET 应保持安全和可重复读取。对写操作还要考虑重复提交和幂等性。

**问：路径参数、查询参数和请求体有什么区别？**

答：路径参数定位资源，例如订单 ID；查询参数表达筛选或分页，例如 `?page=2`；请求体携带创建或更新所需的数据，例如售后类型和原因。

**问：常见 HTTP 状态码分别是什么意思？**

答：200 成功、201 创建、400 请求不合法、401 未认证、403 无权限、404 未找到、409 状态冲突、422 输入校验失败、500 服务端未预期错误。返回哪一个码应结合 API 契约和具体错误语义。

**问：FastAPI 如何决定参数从哪里读取？**

答：先看参数是否出现在路由路径中；路径参数从路径读取。简单参数一般作为 Query 参数；Pydantic 模型一般作为请求体。使用 `Path`、`Query`、`Body` 可以显式声明，避免歧义。

**问：请求进入 FastAPI 后大致经历什么？**

答：请求先通过 ASGI 服务器进入应用和中间件，然后进行路由匹配、参数解析与校验、依赖解析，接着执行路由函数；结果经过响应模型处理和 JSON 序列化后返回。如果过程中出现已处理异常，则由异常处理器生成错误响应。

## 2. Pydantic 与输入、输出校验

### 基础知识

Pydantic 用 Python 类型声明数据形状，并在运行时解析和校验数据。FastAPI 使用它来校验请求、生成 OpenAPI 文档，也可以用响应模型筛选和序列化返回字段。

请求模型描述客户端可以提交什么；响应模型描述服务端承诺返回什么。二者分开能避免客户端传入数据库内部字段，也能避免接口意外泄露内部数据。

常见约束：

- `Field(gt=0)`：必须大于0。
- `min_length`、`max_length`：限制文本或集合长度。
- `Literal[True]`：要求值必须明确为 `true`。
- `Enum`：只允许预先定义的状态或类型。
- 嵌套模型：描述 JSON 内的对象和列表。

校验失败时，FastAPI 通常返回 422 和字段错误信息。响应模型也会校验后端返回值；若后端代码违反响应契约，通常意味着服务端实现错误。

### 面试问题与回答

**问：Pydantic 模型解决什么问题？**

答：它定义数据结构和字段约束，在程序入口把外部数据转换成有类型、有验证规则的 Python 对象，并可用于生成接口文档。

**问：为什么请求模型和响应模型要分开？**

答：两者安全边界和字段需求不同。请求只开放允许用户填写的字段；响应只暴露客户端需要的数据。分开还能让内部数据库结构变化时，外部 API 保持稳定。

**问：`Field(gt=0)`、长度限制和枚举有什么作用？**

答：它们把基本约束放在 HTTP 边界，非法输入可以在进入业务逻辑前被拒绝。枚举避免任意字符串进入状态字段。

**问：FastAPI 如何把 Python 结果变成 JSON？**

答：路由返回 Python 字典、模型或其他可支持的对象，FastAPI 依据响应模型和 JSON 编码规则校验、筛选并序列化成响应体。

**问：请求字段不符合模型会怎样？**

答：请求通常在路由函数执行前校验失败，FastAPI 返回 422。业务服务不必重复处理所有基础格式错误，但业务规则仍要在服务端再次检查。

## 3. 依赖注入与 `Depends`

### 基础知识

依赖注入的意思是：函数声明自己需要什么对象，由框架或装配层创建并传给它，而不是函数内部到处自行创建。FastAPI 使用 `Depends` 声明依赖。

项目路由可以依赖当前用户、数据库 Session 或 Service。依赖还可以嵌套：例如 `current_customer` 依赖 `get_identity_service`，后者又依赖 `get_db`。FastAPI 会解析这条依赖树，并在同一次请求中复用适用的依赖结果。

常见用途：

- 获取当前用户。
- 创建和清理请求级数据库会话。
- 组装 Repository 与 Service。
- 集中做权限前置检查、配置读取等操作。

不要把所有业务规则都塞进依赖函数。依赖主要负责准备请求执行所需的对象；业务决策一般放在 Service 或 Domain。

### 面试问题与回答

**问：依赖注入解决什么问题？**

答：它把对象创建和业务使用分离，让路由更清晰，也便于复用、替换和测试。例如路由只声明需要 `OrderService`，不负责决定数据库连接细节。

**问：FastAPI 的 `Depends` 怎么工作？**

答：路由注册时 FastAPI 记录依赖关系；每次请求到来时，它解析依赖树，调用依赖函数，把返回值注入路由函数参数。使用 `yield` 的依赖还可以在请求处理后执行清理。

**问：依赖可以嵌套吗？**

答：可以。当前用户依赖可以依赖身份服务，身份服务依赖数据库会话。FastAPI 会沿依赖图从底层逐层构造对象。

**问：依赖对象的生命周期是什么？**

答：通常在请求处理期间创建或复用；`yield` 依赖在请求完成后执行清理。具体作用域可通过依赖缓存和作用域配置调整。数据库 Session 在本项目的 `get_db()` 中按请求打开并在结束时关闭。

## 4. 同步、异步与并发

### 基础知识

同步函数调用后会等它完成再继续。异步函数通过 `async def` 声明，在遇到可等待的 I/O 操作时可以用 `await` 让出执行权，使事件循环处理其他任务。

异步的优势主要在大量网络或磁盘 I/O 等待场景；它不会自动让所有代码更快。同步阻塞操作如果直接放在 `async def` 中，会占住事件循环，影响同进程的其他异步请求。

FastAPI 可以处理普通 `def` 路由，也可以处理 `async def` 路由。普通同步路由由框架放到线程池运行；异步路由由事件循环驱动。选型要看整条调用链：数据库驱动、HTTP 客户端和调用的库是否同步或异步。

CPU 密集计算通常需要考虑进程池、独立工作进程或专门任务队列；单纯写成 `async def` 不会释放 CPU。

### 面试问题与回答

**问：`def` 和 `async def` 有什么区别？**

答：`def` 是普通同步函数；`async def` 定义协程函数，调用后得到协程对象，需要由事件循环运行，内部可以 `await` 异步操作。

**问：`await` 做什么？**

答：等待一个可等待对象完成。在等待期间，当前协程可以让出控制权，使事件循环执行其他就绪任务。它不是“新建线程”的意思。

**问：在 `async def` 中调用同步数据库会有什么问题？**

答：数据库调用会阻塞当前事件循环线程，期间其他协程无法在该事件循环上继续运行。若数据库驱动是同步的，简单做法是使用同步路由；异步方案则应使用异步数据库驱动并贯通调用链。

**问：FastAPI 怎样执行同步路由？**

答：普通同步路由函数由 FastAPI/Starlette 放入线程池执行，避免直接阻塞事件循环。具体执行配置会受运行环境影响，但同步调用本身仍然占用线程。

**问：CPU 密集任务和 I/O 密集任务分别如何处理？**

答：异步很适合大量非阻塞 I/O 等待；CPU 密集任务通常使用进程池或独立工作进程，以利用多个 CPU 核心并避免阻塞 Web 进程。

**问：异步并发和多线程有什么区别？**

答：异步通常由一个事件循环在任务等待时切换协程；多线程由操作系统调度多个线程。异步适合协作式 I/O 并发；线程可容纳阻塞 I/O，但 Python CPU 计算还受 GIL 等因素影响。

### 项目代码

当前 API 路由和 SQLAlchemy 使用同步风格，例如 [orders.py](../backend/app/api/routes/orders.py) 与 [session.py](../backend/app/db/session.py)。这套实现对当前学习项目更直接；如果未来改为异步，需要同时调整数据库驱动、Session 管理和所有调用它的业务代码。

## 5. 中间件、CORS 与应用生命周期

### 基础知识

中间件位于请求进入路由前和响应离开路由后的公共路径上。适合处理跨接口的技术问题，例如 CORS、请求追踪、耗时统计和安全头。某项逻辑若只属于售后业务，不应为了“全局”而放进中间件。

CORS 是浏览器执行的跨源访问控制机制。浏览器页面与 API 的域名、端口或协议不同时，浏览器会按 CORS 规则检查服务器是否允许该网页读取响应。简单请求可能直接带来源信息；复杂请求通常会先发 `OPTIONS` 预检，服务器返回允许的来源、方法和请求头后，浏览器才继续实际请求。

**[深入了解]** CORS 的 Origin 判定、预检缓存、凭证请求、`Access-Control-Allow-Origin` 与 `Vary: Origin` 的关系。理解这些细节有助于排查跨域问题，但 CORS 本身不是身份认证或授权。

FastAPI 的 `lifespan` 管理应用启动和关闭期间的资源，例如建立连接、初始化数据或关闭连接。当前项目在启动阶段创建表并按配置导入演示数据；真实生产环境应通过迁移工具管理数据库结构。

### 面试问题与回答

**问：什么是中间件？请求和响应如何经过它？**

答：中间件是包裹应用请求处理过程的公共组件。请求先经过中间件进入路由，响应再沿处理链返回，因此可以统一计时、加头或记录指标。多个中间件的嵌套顺序由注册和框架实现规则决定，调试时应结合应用配置确认。

**问：CORS 是什么？**

答：CORS 是浏览器依据服务器响应头执行的跨源访问限制机制。服务器通过允许的来源、方法和请求头告诉浏览器哪些网页可以读取 API 响应。它不是服务器端鉴权，也不能阻止非浏览器客户端直接调用接口。

**问：中间件适合做什么，什么不适合？**

答：适合做请求 ID、耗时统计、CORS、通用安全头等横切技术逻辑。用户订单归属、退款资格和售后规则应该放在业务服务或领域规则中。

**问：如何处理应用启动和关闭资源？**

答：使用 FastAPI `lifespan`，在 `yield` 前做启动准备，在 `yield` 后释放资源。应用范围的连接池、客户端等资源适合在这里管理；每个请求的数据会话通常放在请求依赖中管理。

**问：`lifespan` 和旧式 startup/shutdown 事件是什么关系？**

答：`lifespan` 用一个上下文表达启动和关闭过程，是现代 FastAPI 推荐的生命周期组织方式；旧式事件处理器是早期分开的启动/关闭钩子。新代码通常优先使用 lifespan。

## 6. 异常处理与统一错误

### 基础知识

异常表示执行中断或失败。Web 层需要把可预期的失败转换成客户端能理解的 HTTP 状态和错误结构；同时不能泄露数据库密码、堆栈或内部实现细节。

`HTTPException` 是 FastAPI/Starlette Web 层异常，适合直接表达 HTTP 错误。领域异常则描述业务问题，例如资源不存在、规则不允许或请求冲突，不绑定 HTTP。统一异常处理器负责把领域异常映射成状态码和 JSON。

### 面试问题与回答

**问：FastAPI 中如何返回错误？**

答：参数格式错误由框架校验并产生 422；Web 路由可以抛 `HTTPException`；业务服务可以抛领域异常，再由统一处理器转换为合适的 HTTP 状态和响应体。

**问：`HTTPException` 和自定义异常有什么区别？**

答：`HTTPException` 绑定 HTTP 语义；自定义领域异常描述业务失败，不要求调用方必须是 HTTP。把领域异常和 HTTP 映射分开，可以让同一个 Service 被 API、Agent 工具或后台任务复用。

**问：为什么 Service 不应该依赖 HTTP 状态码？**

答：Service 是业务层，不应知道调用者是浏览器、Agent 还是命令行。它只报告“订单不存在”或“申请冲突”，由 API 层决定分别返回 404 或 409。

**问：如何统一处理 404、业务校验失败和数据库冲突？**

答：为领域问题定义清晰异常，在 API 层注册统一处理器，集中设置状态码和安全的错误结构。数据库唯一约束冲突应由 Service 捕捉并转换成业务冲突，不能把原始 SQL 错误返回用户。

**问：怎样避免泄露内部错误？**

答：客户端只返回安全的错误码和可理解的说明；详细异常写入受控日志并脱敏。未预期异常使用通用 500 响应，不返回堆栈、SQL、密钥或文件路径。

## 7. 数据库会话、事务与 SQLAlchemy ORM

### 基础知识

- **Engine**：管理数据库连接和连接池，是应用访问数据库的基础设施对象。
- **Session**：一次数据库工作会话，跟踪 ORM 对象和事务状态。它不是数据库连接本身，也不应跨不相关请求共享。
- **ORM 模型**：Python 类与数据库表的映射，例如 `Order` 对应 `orders` 表。
- **Repository**：封装常用 SQL 查询和持久化操作。
- **Service**：根据业务需求组织查询、授权、规则判断和事务边界。

事务把多项数据库操作视作一个整体：全部成功就 `commit()`；失败时 `rollback()`，避免留下部分写入。

`flush()` 会把 Session 中待写入的变化发送到数据库，并可能取得数据库生成的主键，但事务还没有最终提交；`commit()` 会提交当前事务。提交后数据才对其他事务正式可见，事务也结束。

### 面试问题与回答

**问：Engine、Session 和 ORM 模型分别是什么？**

答：Engine 管理数据库连接和连接池；Session 管理一段数据库操作及事务；ORM 模型把数据库表映射为 Python 类和对象。

**问：为什么按请求创建并关闭数据库 Session？**

答：请求之间隔离事务和对象状态，避免并发请求共享 ORM 状态；请求结束后关闭 Session，释放连接资源。连接池通常由 Engine 管理，而不是每个请求新建。

**问：什么是事务？什么时候提交或回滚？**

答：事务保证一组相关写操作共同成功或失败。业务操作完成且校验通过后提交；中途遇到异常则回滚。跨多个步骤创建售后单时，应明确事务边界。

**问：`flush()` 和 `commit()` 有什么区别？**

答：`flush()` 把未提交的变更发送给数据库，可用于提前拿到主键或发现约束错误；`commit()` 才正式提交事务。Flush 之后仍可回滚。

**问：怎样避免 N+1 查询？**

答：发现循环里每条记录都额外查询关联数据时，使用合适的预加载方式，例如 `selectinload` 或 `joinedload`，并通过查询日志或分析确认查询数量。不要无差别地预加载所有关系。

**问：如何避免重复记录？**

答：应用层可以先查询已有记录改善用户体验，但并发请求可能同时通过检查；真正的最终保障应由数据库唯一约束或其他原子操作完成。售后幂等键就是一个例子。

**问：为什么权限过滤最好放在数据库查询条件里？**

答：查询时同时限制资源 ID 和当前用户 ID，可以避免先取到他人数据再忘记在应用层检查，也减少错误暴露数据的机会。项目的订单查询条件就是订单 ID 与 customer ID 一起匹配。

- [models.py](../backend/app/models.py)：订单、商品、用户和售后 ORM 模型。

## 8. 认证与授权

### 基础知识

- **认证（Authentication）**：确认“你是谁”。例如用户登录后建立身份。
- **授权（Authorization）**：确认“你能做什么”。例如只能查看自己的订单。

认证通过不代表可以访问所有资源。授权必须基于可信的服务端身份，并对每个资源执行检查。

常见方案：

- **Cookie + Session**：浏览器持有 Session 标识，服务端保存登录状态。要考虑 Cookie 的 `HttpOnly`、`Secure`、`SameSite` 和 CSRF 防护。
- **JWT**：服务器签发包含声明的令牌，客户端后续携带；资源服务器验证签名和有效时间等信息。
- **OAuth2**：授权框架，描述客户端如何取得访问令牌以及令牌代表什么权限。它不等于某一种 JWT 实现。

**[深入了解]** JWT 的 Header/Payload/Signature、签名算法选择、过期和刷新、撤销策略、密钥轮换；Cookie、CSRF、SameSite 与跨站请求；OAuth2 授权码 + PKCE 的完整交互。

### 面试问题与回答

**问：认证和授权有什么区别？**

答：认证确认用户身份；授权判断该身份能否执行当前操作或访问当前资源。读取本人订单通常需要两者：先得到可信用户，再验证订单属于该用户。

**问：Cookie Session、JWT、OAuth2 分别是什么？**

答：Cookie Session 通常用 Cookie 携带会话标识，状态保存在服务端；JWT 是一种可签名令牌格式，验证后可读取声明；OAuth2 是授权协议框架，规定令牌授权流程。三者解决的问题有关联但不等价。

**问：怎样保护 API 端点？**

答：在路由依赖或认证中间件中验证身份，再在业务服务或数据查询中按用户和资源执行授权；对写操作还要检查业务状态、用户确认和幂等键，并使用 HTTPS 与安全的密钥管理。

**问：如何防止用户修改 ID 后访问别人的订单？**

答：不能只检查订单是否存在。后端从已验证的登录身份取得 customer ID，查询条件同时包含 order ID 和 customer ID。不能使用用户自己在请求体里提交的 customer ID 作为授权依据。

**问：为什么不能信任请求体中的 `customer_id`？**

答：请求由客户端控制，用户可以修改字段。用户 ID 必须来自已验证的服务端身份上下文；请求体中的身份字段不能覆盖它。

**问：如何安全保存密码、Token 和 API Key？**

答：密码应使用专门的慢哈希算法保存，不能明文或可逆加密；访问令牌和 API Key 放在 Secret 管理或受保护环境变量中，避免提交 Git、写入日志或返回前端；按最小权限配置并建立轮换、过期和泄露后的撤销流程。

### MallMate 当前边界

项目使用请求头 `X-Demo-User` 选择演示账号。它是为了本地演示方便，客户端可以自行修改，因此不能作为生产认证。项目的 `current_customer` 会把这个值映射成数据库用户，但真实系统必须换成可信登录方案，并保留“服务端用户 ID + 资源归属校验”的授权链路。

## 复习用：订单接口完整讲解

面试官问“MallMate 如何查询一个订单”时，可以按下面顺序回答：

1. 浏览器向 `GET /api/v1/orders/{order_id}` 发请求。
2. FastAPI 根据路由模板匹配 `get_order`，解析正整数订单号。
3. `Depends` 提供当前演示用户和请求级 `OrderService`。
4. `OrderService` 调用 `OrderRepository`，在 SQL 查询里同时限制订单 ID 和当前用户 ID。
5. 找不到本人订单时抛领域异常，统一错误处理器映射成 HTTP 404。
6. 找到后 Service 整理字段，`OrderResponse` 校验并序列化为 JSON 返回。

这段回答覆盖了路由、参数校验、依赖注入、授权、Repository/Service 分层、异常处理和响应模型，是串起 FastAPI 基础知识的好例子。
