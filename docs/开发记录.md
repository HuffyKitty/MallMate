## 2026-10-13：第一版认证与授权

- 新增 `UserAccount`、`AuthSession` 以及 `Customer.user_account_id`，登录账号与顾客业务资料分离。

- 新增登录、刷新、退出和当前账号接口；刷新 Cookie 使用 `HttpOnly`，Cookie 属性由环境配置控制。

- LangGraph 的持久 State 不再保存顾客身份；Agent 只从请求级 Context 接收服务端认证后的 `Principal`。
- 前端移除演示用户请求头，增加登录、页面刷新恢复会话、401 自动刷新一次和退出登录。
- 引入 Alembic 基线：空数据库可完整建表，已有 SQLite 业务表仅在包含受支持基线必需列时接管；启动脚本与 Docker 都会先迁移再启动 API。
- `scripts/setup.ps1` 在 F 盘项目目录安装依赖，生成被 Git 忽略的随机 JWT 密钥，并保留现有配置值。
- 本轮已安装 Alembic、PyJWT、pwdlib/Argon2 等依赖并应用本地迁移、写入幂等开发账号。按照本轮要求没有执行自动化测试。

- MinIO 的社区 Docker Hub、Quay 镜像和官方二进制下载当前均不可用。新增 `infrastructure/minio/Dockerfile`，从官方 GitHub 的固定开源标签 `RELEASE.2025-04-22T22-12-26Z` 构建本地镜像，避免第三方镜像和漂移的 `latest`。

## 2026-10-14：数据库迁移收尾

- 核对手动种子入口：生产环境和关闭演示数据开关时会在连接数据库前拒绝执行。
- 核对 PostgreSQL 固定业务 ID：种子事务提交前会同步 `orders` 与 `after_sales_cases` 的自增序列。

- 明确拒绝 Alembic `--sql` 离线模式，因为当前迁移必须实时读取目标库的表、列、约束与重复数据。
- 前端会话增加 session epoch，登出或换号后丢弃旧账号的晚到响应；API 请求增加超时处理和面向用户的中文错误提示。

- 后端关键安全配置改为 fail-closed：认证开关、JWT 密钥、Cookie 和生产环境约束不满足时拒绝启动，避免以宽松默认值继续运行。
- Compose 使用的基础镜像均固定到不可变 digest，避免同名标签更新后得到未经确认的构建内容。
- 本地 SQLite 与 Docker PostgreSQL 均已迁移到 `20261014_0002`；PostgreSQL 已确认存在 `uq_order_items_order_id_product_id` 唯一约束。
